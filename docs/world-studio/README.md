## 1. 产品是什么

**事实变了，知道哪些内容该改。**

World Studio 是事实驱动的研究与内容运营工作台。它持续整理一个领域的变化，将证据交给人核对，再把已采用的事实带入选题、网站更新建议和渠道草稿；旧事实被修订后，提醒相关内容的维护者。

这里的 World Model 指可追溯、可修订的行业事实与变化记录，不指物理仿真模型或视频生成模型。内容运营是第一种应用，不另造一份与行业事实库相互竞争的“内容真相”。

它不承诺爆款、无限文章、无人值守发布或全网自动同步。用户不需要先学会使用图谱。

## 2. 第一批用户与价值

首批面向机器人、工业技术、开源硬件领域，持续研究专业信息并对外输出内容的小团队。使用者是内容负责人、研究者与业务负责人；首个内部使用者是 AIMAN.World / 聚身之家。

用户付费购买持续运行与维护，期望减少重复核对和跨渠道修订的时间。付费意愿、续费率和节省时间都是待验证假设，不是当前成果。

第一版不优先服务泛流量铺量账号、大规模代运营账号矩阵，以及金融、医疗、法律等需要独立专业审核体系的领域。第二行业适配是后续通用性验证，不是首版开工的前提。

## 3. 一个产品，三条清楚的边界

| 层 | 保存什么 | 不做什么 |
| --- | --- | --- |
| 行业事实层 | Entity / Claim / Evidence / Relation / Event，以及审核与变化历史 | 不把模型评分、客户观点或传播效果当成事实裁决 |
| 私有工作空间 | 受众、业务事实、表达规则、选题、客户资料、内容和授权 | 不默认进入公共行业库；不把行业 pack 当成客户权限隔离 |
| 内容运营层 | 草稿版本、引用关系、审核决定、渠道执行记录、人工处理项与效果记录 | 不复制一套可独立修改的行业事实；不凭执行请求返回就宣称发布成功 |

同一项公共事实可被多个工作空间引用，但需遵循来源与数据授权。客户的策略、私有事实、密钥和经营数据默认不共享。公开贡献是独立、明确授权的操作，不是默认勾选项。

例如，“整合合作工厂资源”与“拥有自有工厂”是不同事实。写作不能为了强化宣传自动升级后者。未知、冲突、预测和待验证的信息必须保留标签。

## 4. 首版闭环

```text
获授权的来源 / 人工材料
  → 观察与候选信息
  → 身份匹配、去重、证据核对
  → 人工审核与受控事实更新
  → 可追溯的变化记录
  → 查找已登记的内容引用
  → 网站更新建议 + 小红书草稿 / 导出包
  → 人工内容审核
  → 获授权的渠道执行 + 结果核实
  → 真实效果与维护工作回填
```

事实审核与内容审核是两次不同决定。审核通过仅代表在当前证据与范围内采用，不代表永远正确。事实状态沿用核心协议，不另加一套含义相冲突的“已验证”标签。

第一版接入边界：网站先生成更新建议，小红书默认做到经过核实的草稿；没有可靠接入能力时导出内容包并列为人工待办。X 的参考经验可以保留，但不列为首版必须自动接入的第二渠道。

小红书不得自动点击发布。一次内容审核不构成未来所有发布、更新或删除的永久授权；对外执行需要明确的对象、动作、内容版本和有效授权。公开网页不支持编辑时，生成更正处理项，而非伪造“已同步”。

## 5. 第一个演示必须证明什么

使用隔离测试环境里的虚构 Demo Robot A：已采用的载荷从 5 kg 修订为 4 kg，存在产品页、一篇对比文章、一份未发布草稿和一条已发布内容引用它。

预期：保留旧断言及其证据；新证据经审核后产生变化记录；准确列出受影响的已登记内容；草稿原审批失效并需要重新审核；已发布内容进入更正队列。未登记的历史内容显示“覆盖范围未知”，不承诺全部找到。

演示使用 `payload`，它已在机器人 pack 中声明。续航等未声明字段需先评审行业词表，不绕过 pack 校验。虚构数据必须标记为测试材料，不提交到公共 contributions，不写入正式行业库。随后再选择有可核实来源的真实变化做内部验收。

## 6. 首屏与最小功能

首屏依次给出：今天的重要变化、需要核对的证据、待审核内容、需要更新的旧内容、本周实际结果。每个结果应能追到来源与处理记录；图谱和时间线是深入查看入口。

首版必须有来源配置、候选与证据审核、事实到内容的版本引用、变化影响队列、草稿与人工审核、执行结果记录、失败恢复、基本成本记录、导出与迁出能力。不得把不同阶段的存在误报为端到端可用。

不在首版：重建通用浏览器自动化、全平台发布器、行业市场、插件市场、代币激励、复杂账单系统、多行业大规模适配、自动销售决策、未经授权的抓取与发布。

## 7. 开源与订阅

| 提供方式 | 首版原则 | 状态 |
| --- | --- | --- |
| 自部署核心 | 可独立运行，包含基本事实、证据、审核、引用影响、草稿和导出流程；支持自带模型密钥 | 产品目标，尚未实现完整闭环 |
| 官方托管 | 收费承担运行、升级、备份、任务监控和约定范围内的支持 | 服务设计，未上线 |
| 持续行业维护 | 在来源许可范围内提供变化整理与维护；人工核对单独约定边界 | 待试点验证 |
| 社区赞助 | 支持公共研发，不与有交付义务的企业托管合同混同 | 可选治理方式，不是本轮开发项 |

## 8. 安全与服务上线门槛

现有 pack runtime 不是经过验收的多客户托管产品。没有通过身份认证、对象授权、工作空间隔离、日志脱敏、备份恢复和预算限制测试前，不接入外部客户的私有资料，不直接开放演示 API。

执行器必须可替换；AgentDock 是参考接入方式，不要求每个客户拥有同一台 Mac、同一套账号或 AIMAN 内部网络。官方 API、获授权的本地执行与人工导出应如实显示不同能力。

来源文本始终是待处理的数据，不能授予工具权限或改变审核规则。来源失联不等于撤稿；公开更正、授权撤回和访问失败需要不同处理。

## 9. 衡量是否值得继续

优先观察：重要事实的证据可追溯率、影响任务漏检/误报、从采用变化到生成维护任务的时间、每周净节省的人工时间、每工作空间真实成本，以及外部客户是否愿意继续付费。

净节省时间应扣除核对、纠错与平台维护时间。草稿采用率、24/72 小时渠道反馈只帮助改进选题与表达，不能改变事实状态。没拿到数据就记缺失，不记为零。

首版交付门槛与业务假设必须分开记录。详见 [验收记录规则](ACCEPTANCE.md)。
