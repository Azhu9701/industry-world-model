## 3. 拆分方式：独立产品，不复制事实核心

首个开发增量先留在当前仓库的受审阅分支，以最小扩展验证边界；不复制 AIMAN.World 整站，也不因为工作名确定就立即再建一个全栈仓库。

- **核心继续拥有**：事实身份、证据、行业词表、审核到事实更新、历史及版本。
- **Studio 拥有**：工作空间策略、内容与版本、对事实的引用、影响任务、内容审核、渠道执行、成本和效果记录。
- **渠道接入拥有**：能力声明、授权范围、请求标识、外部结果和核实证据；它不修改事实真伪。

需要独立进程或仓库时，先提供版本化接口、冷启动说明与契约测试，再物理拆分。不能长期靠复制业务表或直接读对方 PostgreSQL 来伪装解耦。当前协议已存在的 Snapshot 语义优先复用，必要扩展另开兼容性评审。

## 4. 首个增量要定清的记录关系

以下是设计要求，不是已经存在的表、字段、API 或新协议。

| 记录 | 最小可追溯关系 |
| --- | --- |
| 正式变化 | world / pack 范围、前后版本、采用的贡献与审核决定、变化对象、发生/观察/采用时间及精度 |
| 内容引用 | workspace、内容 ID 与修订版、来源 world 身份、事实 ID、采用版本、证据定位、引用片段 |
| 影响任务 | 变化 ID、内容修订版、影响理由、动作建议、处理状态和覆盖范围 |
| 内容审核 | 审核人、明确权限、内容 hash/修订版、引用版本、决定、时间；内容或关键证据变化后审批失效 |
| 渠道执行 | workspace、账号/目标、动作、内容版本、授权引用、稳定请求键、外部 ID、结果证据与核实时间 |
| 效果记录 | 渠道/内容 ID、观察窗口、采集时间、指标口径、分母、来源与缺失原因 |

引用键必须带来源 world 和 pack，不能仅凭裸 ID 或名字跨库关联。事实内嵌摘录可以用于审核与历史留存，但它是不可独立修改的引用副本，不是事实来源。

允许同一来源链接对应多次观察。修订不能仅靠 URL 判断；事实审核需要区分事件时间、来源发布时间和抓取时间。公开资料只保存验证必要的定位、hash 或获许可片段。

变化触发可用轮询或持久队列；首版不强制微服务或消息平台。正式事实提交与待通知变化需要原子性保证，消费者按 workspace + change + content revision 去重，并在中断后恢复。具体 outbox/游标实现另行评审。

渠道能力至少区分导出、创建草稿、读取草稿、发布、编辑已发布内容与结果核实。未知结果不算成功，也不自动重试制造重复内容；先核实外部状态，核实不了则转人工。

## 5. 可执行开发项

全部为待开始的开发项，不是已创建的 GitHub issues，也不是已完成实现。每项完成时需要关联代码提交与对应验收记录。

| 编号 | 工作项 | 依赖 | 完成证据 |
| --- | --- | --- | --- |
| WS-01 | 准备隔离测试环境、只含虚构内容的载荷修订样例和最小契约测试 | 本文评审 | 样例与正式 contributions 隔离；固定 expected diff / 影响集合 |
| WS-02 | 补齐受控审核、证据读回、事实 materialization 与持久变化记录 | WS-01 | 拒绝过期审核；同事务更新及回滚；历史与 evidence 读回；禁止 Agent 绕过审核 |
| WS-03 | 内容登记、版本引用与变化影响定位 | WS-02 | 找全样例登记引用且没有误报；能重放变化；声明未登记内容的覆盖缺口 |
| WS-04 | 最小工作台与草稿审核：变化、证据、影响、草稿、处理结果 | WS-03 | 审核绑定确切版本；事实改变使旧审批失效；用户能从结果追到证据 |
| WS-05 | 网站建议、小红书草稿/导出适配及结果核实 | WS-04 | 小红书不自动发布；导出不冒充草稿；异常结果可恢复且不重复执行 |
| WS-06 | 认证授权、私有工作空间、密钥与日志边界 | 与 WS-02 并行；外部数据之前完成 | API、任务、缓存、搜索、导出、日志均不能跨客户泄露；不能相信请求方自报 workspace |
| WS-07 | 配额、真实成本、失败恢复、备份恢复和导出迁出 | WS-06；与 WS-04 并行 | 超预算停止；失败调用如实计成本；恢复后仍保留证据与授权边界 |
| WS-08 | 聚身之家真实内部试用与首个外部付费试点 | WS-01—WS-07 对应验收通过 | 真实变化记录、人工耗时、费用、缺口和客户反馈；不把意向当续费 |

最近的实现目标是 **WS-01 → WS-02 → WS-03**：先证明一项事实修订能可靠地变成准确的内容维护任务，再扩展更多内容生成与渠道功能。WS-06 的数据归属设计应在持久化设计阶段同步完成，不能最后补一层登录页面了事。
