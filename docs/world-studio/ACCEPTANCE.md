# World Studio — 首版验收 v0.1

状态：验收设计；**下列 20 项全部为 NOT RUN（尚未执行）**。
日期：2026-10-13。关联：[产品边界](README.md) · [实现路线](IMPLEMENTATION.md)。

这些测试描述未来交付必须满足的行为，不声明现有代码已经通过。文档检查、单元测试、真实业务核实分别出具记录，不能互相替代。

## 1. 环境与材料

受控测试环境使用虚构 Demo Robot A 的载荷修订，不使用真实客户资料、账号密钥或公开发布动作。为每个用例固定输入、期望变化、应受影响的内容集合及不应受影响的集合。虚构材料不得进入正式 contributions 或公共行业库。

内部业务验收另选能从公开原始来源核实的真实变化，记录发生时间与抓取时间。来源失联、冲突、身份不确定和不可自动处理的渠道，要作为正式结果保留，不得人为删掉失败样本。

G1 为内部闭环；G2 为外部订阅试点。在未具备外部数据安全条件前只运行隔离的虚构资料。所有适用门槛必须通过；不能拿“整体通过率较高”豁免数据泄露、误发或错误采用事实。

## 3. 验收记录格式

每次运行记录：用例 ID、实现提交、环境标识、执行时间与时区、fixture 版本/hash、前置条件、预期、实际结果、证据路径、PASS/FAIL/BLOCKED/NOT RUN、复核人和剩余问题。

没有真实运行证据只能是 NOT RUN；环境条件缺失是 BLOCKED；断言不满足是 FAIL。修复后保留原失败记录，并新增复测记录。避免把含客户正文、登录信息或密钥的截图和日志上传到公共 PR。

## 4. 产品试点门槛与业务假设

技术验收与商业验证分开：通过 A01—A20 不等于客户愿意续费；客户愿意付费也不能豁免安全项。

建议先连续进行 14 天内部试用，覆盖至少 10 个经核实的真实变化，逐个记录受影响内容、审核工作、未完成项和人工耗时。这些是试点设计目标，不是当前成果，也不是保证节省时间的样本量结论。

外部试点至少有一个独立团队能完成闭环并获得费用与服务范围说明。记录首次付费、再次付费与主观意向的差别，不把承诺续费当成实际续费。价格、运行频率和支持工时据真实成本再调整。

对任何公开成果陈述，至少区分：只完成文档、已有实现未验收、测试通过、真实内部使用、外部试点、正式服务。
